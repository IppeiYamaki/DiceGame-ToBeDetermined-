# DiceGame 新ルール・実装方針まとめ

## 概要

このプロジェクトは、**所持している6個のダイスからターン開始時にランダムで3個を振り、出目合計と役倍率からActionPointを得て、そのActionPointを消費して攻撃・防御・スキル・アイテムを使うターン制ダイスバトルゲーム**として再設計します。

旧仕様では、3個のダイスを手動選択し、面ごとのAttack/Defense属性を集計していました。新仕様では、ダイス面は属性を持たず、各面の数値だけを持ちます。出目合計に役倍率を適用した値をActionPointとして扱い、プレイヤーはActionPointが尽きるまで複数の行動を選べます。

さらに、プレイヤーの行動は即時実行ではなく**行動予約レーン**に積み、行動決定ボタンを押したタイミングで予約順に順次実行されます。敵は1体固定ではなく複数体を可変で配置でき、敵の数に応じて自動整列されます。

---

## ゲームジャンル

- ダイスバトルゲーム
- ターン制バトル
- ダイス構築型ゲーム
- ActionPoint消費型コマンドバトル
- 役・コンボによるActionPoint強化あり
- ラン中にダイス、スキル、アイテムを入れ替えて強化するローグライク拡張向け構造

## 基本ルール

### 1. プレイヤーは6個のダイスを持つ

プレイヤーはラン中、基本的に6個のダイスを所持します。

- 初期状態では通常の6面ダイスを6個持つ想定です。
- ダイス入手イベントや戦闘報酬では、所持ダイス数を増やしません。
- 新しいダイスを入手する場合は、既存6枠のいずれかと交換します。
- 所持ダイスは `RunPlayerManager` のラン中Player情報として管理します。

### 2. ダイス面は数値のみを持つ

新仕様では、ダイス面のAttack/Defenseなどの特殊属性を廃止します。

各面が持つ情報は以下です。

- 目の値

通常の6面ダイスは `1, 2, 3, 4, 5, 6` の値を持ちます。特殊ダイスでは、以下のように面ごとの値を自由に変えられます。

```text
例: 2, 2, 4, 4, 6, 8
```

将来的には6面以外の多面ダイスも扱います。

```text
例: 8面ダイス 1, 2, 3, 4, 5, 6, 7, 8
例: 特殊8面ダイス 1, 1, 3, 3, 5, 5, 7, 10
```

現在の `DiceDefinition` は `DiceFaceData[]` を持つため、面数可変の設計と相性があります。

## 戦闘ルール

### 戦闘の基本フロー

1. ターン開始
2. プレイヤー所持ダイス6個からランダムで3個が選ばれる
3. 選ばれた3個のダイスをロールする
4. 3個の出目合計を計算する
5. 出目で役が成立する場合、役倍率を出目合計へ乗算する
6. 倍率適用後の値をActionPointとして保持する
7. プレイヤーはActionPointを消費して攻撃、防御、スキル、アイテムを**行動予約レーンに予約**する
8. 予約は実行前であればキャンセルでき、キャンセル時はAPが返却される
9. 行動決定ボタンを押すと、予約した行動が予約順に順次実行される
10. 防御に割り振った値がBlockとして反映される
11. 生存しているすべてのEnemyが行動する
12. 勝敗を判定する（全敵撃破で勝利）
13. 決着していなければ次ターンへ戻る

### 行動予約レーン

プレイヤーの行動はすべて一旦「行動予約レーン」に積まれます。

- 攻撃/防御/スキルは予約時点でAPを確保（消費）します。
- アイテムはAPを消費せず予約でき、消費（所持数減少）は実行時に発生します。
- 予約エントリにはキャンセルボタンがあり、キャンセルすると確保したAPが返却されます。
- 行動決定ボタン（旧: ターン終了ボタン）で予約を順次実行し、その後敵行動に移ります。
- 予約の対象敵が実行前に撃破されていた場合は、生存している敵を自動選択します。

### 複数敵とターゲット選択

- 敵は `ActionPointBattleSceneController` の敵リスト（`List<EnemyDefinition>`）に登録した数だけ出現します。
- `EnemyAreaView` がEnemyView Prefabを動的生成し、HorizontalLayoutGroupなどで自動整列します。
- 敵をクリックするとターゲット選択でき、スキル/アイテム/ボタン攻撃の対象になります。
- 攻撃のドラッグ&ドロップはドロップ先の敵を直接対象にします。
- 撃破された敵はエリアから取り除かれ、残りの敵が自動で詰め直されます。
- 行動の対象分類は `ActionTargetType`（Self / SingleEnemy / AllEnemies / RandomEnemy）で定義し、`SkillDefinition` と `ItemDefinition` が保持します。

## ActionPoint

ActionPointは、そのターン中にプレイヤーが使える行動コストです。

計算式:

```text
ActionPoint = Floor(3個の出目合計 × 成立役倍率)
```

例:

```text
出目: 2, 4, 6
合計: 12
役: 偶数 x1.5
ActionPoint: Floor(12 × 1.5) = 18
```

ActionPointはターン中に消費されます。ターン終了時に残ったActionPointは基本的に次ターンへ持ち越しません。

## プレイヤー行動

### 攻撃

攻撃はActionPointを消費する標準コマンドです。

- 攻撃UIには上下ボタンを用意します。
- 使用するPtを増減できます。
- 攻撃値は基本的に消費したActionPointと同じ値です。
- 攻撃枠内の増減ボタン以外をクリックし、そのまま攻撃したい敵までドラッグ&ドロップすると、その敵を対象に攻撃が予約されます。
- ボタン実行でも予約できる最小実装を用意します（選択中のターゲット、未選択なら生存敵を自動選択）。
- 予約時にAPを確保し、実行は行動決定ボタン押下時です。

```text
消費AP: 7
攻撃値: 7
```

### 防御

防御もActionPointを消費する標準コマンドです。

- 防御UIには上下ボタンを用意します。
- 使用するPtを増減できます。
- 防御は即時Blockではなく、ターン終了時に設定値がBlockとしてプレイヤーに付与されます。

```text
防御予約: 5
ターン終了時: Player Block +5
```

### スキル

スキルはラン中に入手し、プレイヤーが所持します。

- スキルごとに固定コストがあります。
- 発動ボタンを押すとActionPointを確保して行動予約レーンに積まれ、行動決定時に効果を発動します。
- 効果種別は Heal / Damage / Block / GainActionPoint / ApplyStatusEffect に対応します。
- ApplyStatusEffect の場合は `StatusEffectDefinition` をスキルに設定し、実行時にプレイヤーへ付与されます。
- `1戦镘1回のみ使用可能`（OncePerBattle）のスキルは、同一戦闘中に再使用・再予約できません（戦闘開始時にリセット）。
- `使用時SE`（AudioClip）を設定すると実行時に再生されます。
- 対象分類は `ActionTargetType` で定義します（Self / SingleEnemy など）。
- 最大所持数があります。
- 最大所持数を超える場合は、既存スキルとの交換を行います。

例:

```text
スキル: 応急処置
コスト: 10
効果: HPを5回復
```

### アイテム

アイテムもラン中に入手し、プレイヤーが所持します。

- アイテムマスタは Yasuda版 `ItemData` を使用します（旧 `ItemDefinition` は廃止）。
- 効果（効果種別・効果量・対象タイプ）は Yamaki側の `ItemEffectTable` で定義し、`RunPlayerManager` に登録します。Yasudaフォルダは変更しません。
- 所持は `OwnedItemStack`（`ItemData` + 個数）のスタック管理です。同一アイテムは1枠にまとまります。
- 戦闘中はアイテム一覧UI（`ItemListView`）に所持アイテムがスタック表示され、表示数は「所持数 − 予約済み数」です。
- 使用ボタンを押すと行動予約レーンに積まれ、行動決定時に効果を発動・消費（個数減少）します。
- APは消費しません（予約・実行ともにコスト0）。
- 同一アイテムは所持数を超えて予約できません。
- 対象分類は `ActionTargetType` で定義します。
- 最大所持数（スタック種類数）があります。同一アイテムの追加は個数増加として扱われます。
- 効果は回復、ダメージ、Block付与、ActionPoint増加などを想定します。

## 役システム

3個のダイスの出目から役を判定します。

役は `DiceRoleDefinition` により `ScriptableObject` として定義します。

作成メニュー:

```text
Create > DiceGame > DiceRoleDefinition
```

役には以下の情報があります。

- 役名
- 説明
- 倍率
- 成立条件タイプ
- 判定用数字リスト
- 必要一致数

複数の役が成立した場合は、最も倍率が高い役が採用されます。同じ倍率の場合は、登録リストの先頭にある役が優先されます。

### 想定役

| 役 | 出目例 | 倍率例 |
|---|---|---:|
| ピンゾロ | `1,1,1` | `3.0` |
| ゾロ目 | `2,2,2` ～ | `2.0` |
| 偶数 | `2,4,6` など | `1.5` |
| ワンペア | 同じ数字が2個以上 | `1.2` |
| シゴロ | `4,5,6` | 未定 |
| ヒフミ | `1,2,3` | 未定 |

### 成立条件タイプ

| 条件タイプ | 内容 | 例 |
|---|---|---|
| `ExactNumbers` | 指定した数字構成と完全一致。順不同 | `1,1,1` / `4,5,6` |
| `AllSame` | 3つすべて同じ数字 | `3,3,3` |
| `AllInAllowedSet` | 指定された数字セット内だけで構成 | 偶数のみ、奇数のみ |
| `SameNumberCount` | 同じ数字が指定数以上ある | ワンペア |

## System / Player の常駐設計

新仕様では、バトルシーンだけがプレイヤー情報を持つ設計をやめます。

ゲーム全体で参照できる常駐オブジェクトとして、以下を用意します。

### Systemが持つもの

`RunSystemManager` が担当します。

- オプションで変更する設定
  - マスター音量
  - BGM音量
  - SE音量
  - 将来的なキーコンフィグなど
- 共有で使うTextureやIcon設定
  - バフ/デバフアイコン
  - 攻撃/防御/スキルなどのアイコン
- ダイス役一覧の参照
- DiceMasterRegistryの参照
- StatusEffectRegistryの参照
- ラン経過時間

### Playerが持つもの

`RunPlayerManager` が担当します。

- プレイヤー名
- プレイヤーの現在HP
- プレイヤーの最大HP
- 所持ダイス6枠
- 所持スキル
- 最大スキル所持数
- 所持アイテム（`OwnedItemStack`: `ItemData` + 個数）
- 最大アイテム所持数
- `ItemEffectTable` 参照（アイテム効果の解決用）

戦闘中だけの一時値は、基本的に `ActionPointBattleSceneController` が持ちます。

- 現在ActionPoint
- ターン開始時に獲得したActionPoint
- 現在Block
- 防御予約値
- 現在ターン番号
- 行動予約キュー（`PlannedAction` のリスト）
- 選択中のターゲット敵インデックス
- 各敵のランタイム状態（`EnemyUnitRuntime`: HP / Block / 次回行動）

### 常駐化の方法

`RunSystemManager` と `RunPlayerManager` は `DontDestroyOnLoad` によりシーン遷移後も破棄されないGameObjectとして作成します。

- タイトル/ラン開始シーンで生成する
- すでに存在する場合は重複を破棄する
- 各シーンは `RunSystemManager.Instance` / `RunPlayerManager.Instance` を参照する

## 旧仕様との差分

既存の `BattleSceneController` は旧仕様ベースです。

旧仕様:

- 6個から3個を手動選択
- ロール結果を即攻撃値として敵HPへ反映
- 攻撃後すぐ敵行動
- ActionPointを保持しない
- 防御予約や複数行動がない

新仕様:

- 所持6個からターン開始時にランダム3個を自動ロール
- 出目合計 × 役倍率をActionPointとして保持
- ActionPointを攻撃、防御、スキル、アイテムに消費
- 行動は即時実行ではなく行動予約レーンに積み、行動決定ボタンで順次実行
- 予約は実行前ならキャンセル可能（AP返却）
- 防御は予約実行後にBlockとして反映
- 敵は複数体を可変で配置でき、自動整列・クリックでターゲット選択
- Player HPや所持ダイス・スキル・アイテムは `RunPlayerManager` が保持する
- アイテムは Yasuda版 `ItemData` + `ItemEffectTable` + `OwnedItemStack` で運用（旧 `ItemDefinition` は廃止）

旧Controllerは参照用に残し、新仕様では `ActionPointBattleSceneController` を使用します。
